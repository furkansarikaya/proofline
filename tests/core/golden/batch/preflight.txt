## Stop rules

- a task that needs anything else is parked with its question and the batch goes on; a task that depends on it is skipped
- every task works in its own git worktree (.agents/local/worktrees/<ID>, made from the canonical branch just before the task starts): a parked task, one waiting for its merge and one in a CI-fix round keep theirs and block no task that does not depend on them; the main working tree is never touched. A task starts only when every task it depends on is merged; a merged task's worktree is removed
- after every merge the lead checks the CI run of the merge commit itself (not the latest run, agent.sh batch-ci): the batch stops when that run is red, still running after batch.ci_wait_minutes (30), or when no run for it appears within batch.ci_appear_minutes (10)
- the batch stops when the session closes, a usage limit is hit or the computer sleeps; the same approved batch continues with /proofline batch and never runs a merged task again

## NOT covered (each stays a question the batch parks on)

- a waiver of a finding, a scope expansion, a new dependency, a reopen of a FAILED or BLOCKED run
- a destructive or single_step data change, a rule promotion, sending the friction report, a new fix-round budget
- a mutation budget above the cap, and any CRITICAL task

## Not in this batch

- none

The batch runs in THIS session, task after task; there is no background process. It stops when the session closes, a usage limit is hit or the computer sleeps. Keep the computer awake (plugged in, lid open) and this session open.
