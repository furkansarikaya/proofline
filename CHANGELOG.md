# Changelog

## Unreleased

- `skills/evidence-map/SKILL.md` no longer shows "Error in user YAML" on GitHub: three skill descriptions (`evidence-map`, `exploit-proof`, `proof-review`) held `: ` in a plain YAML scalar and are now quoted (`proof-review` also shortened under the 1024-character limit); new `tests/skills/frontmatter.test.mjs` checks every front matter, YAML and TOML file and Markdown link, anchor, fence and table, and runs in CI for documentation-only pull requests too; `generate-skills.sh` unquotes quoted descriptions; one broken anchor in `LIFECYCLE.md`, one stale README link and unescaped `|` in four template tables fixed (A125).
- The e2e harness records the project database before any lead starts and after the run (A121, amends A95): `db-probe-before.txt`, `db-probe.txt` (schema, row counts, applied migrations, `legacy_notes` count, hash and values, file sha256, read from a byte copy), `db-probe-diff.txt` and `db_unchanged=yes|no` in `summary.txt`, so CRITICAL K-9 can be judged.
- The debug-proof guard of `handoff IMPLEMENTED` also fires when the task's Goal, Context, Acceptance criteria, Constraints, Risks or the user's quotes speak of a defect or a fix (A122, amends A35, A105): a bug fix whose title has no defect word can no longer reach CODE_DONE without `reports/NNN-debug.md`.
- A fix round may also touch a frozen plan-scope path that shares an acceptance criterion with a path of a failing finding (A123, amends A60, A77): the fix bound was the finding paths only, so a fix needing another file of the approved plan was refused and forced a second plan approval; paths outside the plan scope or sharing no criterion stay refused, `agent.sh next` (open fix round) and the refusal print the allowed paths (`fix_path=` lines) and name the scope-approval, amendment and `refreeze` route for any other path.
- Write, Edit, MultiEdit, NotebookEdit and `apply_patch` are refused outside the project copy, registered worktrees and the runtime's memory, tool-results and plans folders (A120, amends A97): a run left `DESIGN.md` in a mangled sibling directory; a path sharing the project prefix is outside. The e2e harness replies to a question only while one is open (`tests/e2e/question-open.sh`): four scripted replies had answered a stop that asked nothing.
- `sed -i` followed by an option-looking word (`sed -i -E`, `-i -n`, `-iE`, `-i-E`) is denied by the hook because BSD sed takes it as the backup suffix and leaves a stray `<file>-E`; new lead-only `agent.sh discard-stray <ID> <file-name>` removes one stray top-level regular file of a run directory (ledgered with its sha256; never a protected name in any case, symlink, directory or sub-path), and the "unexpected run artifact" refusal names it (A119).
- A stale-lock break in `acquire_lock` never strips a live holder of its pid (A118): the dead holder's `pid` file is renamed aside and the lock removed only if the file still names the dead holder, else it is put back. Fixes a rare double-holder race under parallel commands; `gates-test` fixtures also date captures one hour ahead and no longer let fixture cleanup decide the exit status.
- `agent.sh cleanup <ID>` also removes the run's `.agents/local/assignments/<ID>/` directory (A116): after the existing cleanup preconditions, never following a symlink, leaving other runs' assignment directories alone; a refused cleanup leaves both directories.
- `.claude/` is ignored as a whole in this repository (A117); `proofline init` still never adds it to an installed project's `.gitignore` (now tested); `tests/e2e/run.sh` removes its project copy and isolated Codex home on every exit through a trap, and evaluators must remove their own scratch output.
- A TRIVIAL freeze refuses a scope with executable code (A115, amends A31, A61): `freeze` and `refreeze` (the only entries to a frozen plan; IMPLEMENTING verifies that frozen plan hash) fail a TRIVIAL plan whose `## Scope` holds a file matching `review.executable_code` (tests included) with "classify STANDARD", so code is no longer scoped under TRIVIAL and found only at IMPLEMENTED; `next` and the lead lifecycle say a plan that changes code or adds tests is STANDARD or higher.
- A non-TRIVIAL plan (STANDARD, COMPLEX, CRITICAL) with a `## UI` section must declare `visual_writes:` at plan time (A112, amends A78/A81/A82/A98): `validate-plan` and `agent.sh freeze` refuse it without the line, so QA visual no longer ends INCONCLUSIVE and forces an amendment and a second plan approval; TRIVIAL (no QA gate) unchanged.
- Headless Claude workers started by `dispatch.sh` get an explicit `--permission-mode` (A114, amends A46, A56): config `dispatch.claude_permission_mode` (`bypassPermissions` default, `acceptEdits`, `default`; validated by `config-check`), recorded in the ledger and the dispatch line; `bypassPermissions` is refused (BLOCKED, naming `proofline doctor`) while the PreToolUse hook is not wired in `.claude/settings.json`. Fixes mixed-runtime and failover runs stalling at IMPLEMENTED because a default-mode worker could not `submit`. Codex dispatch is unchanged.
- Every `git stash` subcommand (list and show included) is denied to a specialist in the project's working tree, including `git -C <project> stash ...`, `--no-pager`, `cd <project> &&` and `sh -c` spellings; registered evidence worktrees stay free and the denial names them; a path the hook cannot resolve from the text (unexpanded variable other than a leading `$TMPDIR`/`$HOME`, substitution, `cd -`, `pushd`, a `cd` inside a subshell or pipe) is read as the project, so use a literal path that exists, and create an evidence worktree in a separate call; an unquoted substitution before `stash`, a wrapper (`find -exec`, `watch`, `ssh`, `su -c`, ...) or a variable where the subcommand goes is denied by a text safety net (A111, amends A71).
- An explorer's report name is allocated by `submit` (A113, amends A43): the explorer passes `--report <file>` and the script picks the next free `reports/NNN-explorer.md` atomically, so parallel explorers no longer overwrite each other (a third explorer result in a COMPLEX run); a direct write into a numbered explorer path is refused, and `dispatch.sh` claims its sequence atomically.
- Self-test shards are balanced by measured unit weight and CI runs six shards (A109, amends A76): the slowest shard no longer takes 12 to 14 minutes; every unit still runs exactly once. `SELFTEST_LIST` and `SELFTEST_SLOWEST` show the split and the timings.
- visual-proof browser measurement is its own CI job (`visual-browser`, Linux and macOS, main/nightly/manual) on the runner image's own browser, and `measure.mjs` retries a browser start timeout once with the browser's stderr tail in the message (A110, amends A82); verified on `ubuntu-latest` with `--no-sandbox`.
- Approval detection is fail-closed (A108, amends A41/A68/A79): a reply approves only when every word is part of an allowlisted English or Turkish approval phrase, the kind's own words or a short filler list, and it holds a phrase and the kind word; any other word (a negation, a hesitation, an extra clause), an empty or an unrelated reply is neither approval nor rejection, the request stays pending and `next` says to ask again; case folding is locale independent; every approval question lists the accepted answers.
- A report is not evidence (A107, amends A93, A102): `submit` runs the skill validator of the role and focus itself and refuses a declared `--validator-result` that differs or a PASS the validator computes as FAIL; every cited evidence file (`--evidence PATH[@SHA256]`, or `PATH@<sha256>` in a row or the report) must exist inside the run with the cited hash, checked at `submit` and again at `record`; a PASS re-runs the recorded reproduced commands that are configured or planned and a different exit status or output line is FAIL with a blocking finding
- Approval single-use is per capture, not per text (A106, amends A41/A68): `approve` records `capture_id` (`session:time:sha256`) and refuses reuse of one capture for a second approval of the same kind; a new, newer capture with identical words answers a new request (a re-requested plan can be approved with "Plan approved." again).
- Run language comes from the user's own words (A103, amends A99): `run-language` reads TASK.md `Language:`, then the TASK.md `>` blockquote, then the oldest captured prompt of six or more words; short replies such as `approve commit` and newer English system prompts no longer flip a Turkish run to English.
- `submit` stdin contract (A104): `--report -` with `--findings -` (or any two `-` sources) is refused before stdin is read with the corrected command, except one stdin document split on the exact line `=== FINDINGS ===` (report above, rows below); `--findings none` is zero rows, an answer-only task uses it or one `info|-|answer|<line>` row; rejected rows and empty reports name the corrected form; role texts, dispatch prompt and skills agree.
- A defect the request does not ask for is declared, never folded into the task (A105, amends A60): a COMPLEX or CRITICAL TASK.md whose request names no defect but whose Context, criteria, constraints or risks speak of a defect or a fix needs a `## Pre-existing defects` entry (`decision: report | fix`; a `###` heading counts); `freeze`, `refreeze`, `handoff IMPLEMENTING`, `next` and `validate-task.mjs` enforce it, a `decision: fix` still needs the user's own `scope` approval, and a blanket "use your recommended option" never decides a scope fix in INTENT.md.
- `freeze` and `refreeze` validate the PLAN.md scope mapping (every entry needs `path` and `criteria:`, scope not empty) with the check `handoff IMPLEMENTING` uses, before recording any freeze state (A101): a plan without `criteria:` can no longer freeze `scope_paths: ""` and trap a TRIVIAL run at a scope approval.
- UNSUPPORTED needs evidence (A102, amends A98): `submit --result UNSUPPORTED` also takes `--evidence <file>`, the skill validator's own saved output, snapshotted like the report; `record` refuses it unless the file holds `RESULT: UNSUPPORTED` (visual: or `INCONCLUSIVE`), its sha256 matches and a printed `BASE:` is the run's base. It also refuses a contract UNSUPPORTED when a contract file the control plane found in the diff is missing from contract-proof's new `FILE: compared|unsupported <path>` lines (or all are compared), and a migration UNSUPPORTED when a changed `.sql` migration is not listed by `validate-migration.mjs --repo`, which now prints `RESULT:` and `FILE: unsupported <file>`. `concurrency` and `config` no longer accept UNSUPPORTED. The gate record keeps `unsupported_evidence: <path>@<sha12>` (stale if the file changes), and `pipeline` and `next` print it. Capability probes refuse a `visual` UNSUPPORTED when a Chromium-family browser or an installed browser-test dependency exists, and a `performance` UNSUPPORTED when the project has a benchmark command; INCONCLUSIVE evidence needs a `<focus> INCONCLUSIVE:` reason (and UNSUPPORTED evidence refuses one); evidence must be the submitting role's own file.
- End-to-end harness (A100): `E2E_CODEX_MODEL` and `E2E_CODEX_EFFORT` add `-m` and `-c model_reasoning_effort` to the Codex lead and resume commands (the dry run prints them), and the Codex effort ladder accepts `none` as an explicit override; class floors are unchanged.
- The approval, assumption and failover questions the control plane prints follow the run's language (A99): Turkish in a Turkish run, with `approve`, `reject`, `accept AS-n`, kind words, ids and hashes unchanged; English runs are unchanged.
- UNSUPPORTED is unproven and reported, not blocking by default (A98): a risk focus whose tool or capability is missing is recorded `unsupported` (never `pass`), its gate can close, `pipeline` and `next` show `UNSUPPORTED (unproven, reported)`, and the completion report must list every such check under `## Unsupported Checks` with `not proven: <what>`. `risk.unsupported: block` restores the blocking rule of A78; an INCONCLUSIVE measurement (`performance INCONCLUSIVE:`, including unverified performance thresholds, `visual INCONCLUSIVE:`) and a FAIL stay blocking. A vague reason (`n/a`) is refused, `summary` shows `pass (unsupported: <focus>)`, and `next` asks the lead to surface unsupported checks to the user.
- TRIVIAL runs no longer dispatch a designer for a UI path (A96): a `ui_path` or `ui` signal of a TRIVIAL run is printed with `check=- (class TRIVIAL: no design phase / no QA gate)`, adds no missing-flag finding and names no design role, so a copy fix in an `.html` file keeps the minimal plan and no `design/` folder. The capability expectations N-2 (`## Risk` only when risk flags or flag-requiring signals exist) and N-3 (dispatch records only when `dispatch.sh` was used) are scoped accordingly.
- C-18 and S-6 (A97): the runtime hook refuses every shell write outside the project and its registered worktrees (`~`, `$HOME`, `$TMPDIR`, `/tmp`, any absolute path; `/dev/*` stays allowed) and names `.agents/runs/<ID>/scratch/`; `agent.sh worker-evidence` refuses GREEN and REFACTOR without an earlier RED for the path, and GREEN without an implementation change since that RED
- End-to-end harness (A95): global git config hash before and after (C-18), replies logged by kind, pipeline, insights, metrics and visual artifacts collected, and `tests/e2e/expected/CAPABILITIES.md` (N-1 to N-6) scored separately; existing expectations unchanged.
- Review round on three skills (A93): performance-proof pins the bootstrap seed, resamples and confidence (no `--seed`), ties the direction to the unit (a time is lower-is-better), never submits a PASS whose thresholds were not recomputed from config and plan, and bounds config percentages to (0, 100]; visual-proof pins every threshold to the documented value or a stricter one, allows `not_applicable` only for the fixed nothing-to-measure items (counted apart in `SUMMARY`), blocks and records every request outside the page's origin, states the A50/A52 database rule, and submits INCONCLUSIVE as UNSUPPORTED (`visual INCONCLUSIVE:`) like performance-proof; concurrency-proof no longer lets `pre_existing`, `closed` or `accepted` close a traced finding without proof (`--base` diff, a structured recheck, a `--plan`/`--spec` quote) and cross-checks the candidate count. Re-review: unit aliases and plan-declared directions, fix rechecks inside the traced function with a synchronisation token, hashed reproduction rechecks of the original command, `accepted_by` naming the finding in a frozen plan, workers/WebSockets/service workers guarded and same-origin writes recorded in visual-proof (at most INCONCLUSIVE without an allowance or without the guard), contrast 3 only for measured large text, a server-backed network check and a sturdier abort check.
- Skill validator hardening after an independent review (A94): lead `check-result.mjs` accepts the risk-focus and UNSUPPORTED results `agent.sh` accepts; contract-proof `--path` adds to discovery and a mistyped or unchanged path is UNSUPPORTED, union members and negated plan bullets are classified; data-design token-scans non-SQL migrations (unanalyzed files are listed, never skipped) and `validate-migration.mjs --repo` cross-checks destructive flags; exploit-proof reports unknown manifests, lockfile host swaps and negated plan mentions, and a missing plan caps the confidence at low; proof-review config compares by line position and re-derives from the repository; evidence-map handles CommonJS exports, `.vue`/`.svelte` and reports files over 1 MiB; ui-design refuses meeting-based approvals; the benchmark reads trap and planted-fact sections; the shipped dependency-manifest signal lists every manifest the diff reads.
- Control-plane review fixes (A92): a contract found by content raises its signal on edits and deletions too, config JSON such as tsconfig no longer counts as a contract, a risk FOCUS cannot buy a second NEEDS_INPUT round, assumption acceptance refuses reject/or/instead, `next` offers no fix round for UNSUPPORTED or missing-flag failures, a missing `freeze.risk_sha256` is inserted by freeze and fails closed on verify, and metrics gate labels follow the tier.
- New skill `performance-proof` (A87) for the REVIEW `performance` focus (`performance_critical`): the project's own benchmark command runs in a base and a change worktree, interleaved (`run-bench.sh`), with the environment recorded; `compare-bench.mjs` reports median, MAD, IQR and a seeded bootstrap interval and decides PASS, FAIL or INCONCLUSIVE by a rule calibrated with a seeded simulation (default threshold 10 % on the median; `.agents/config.yaml` `performance:`, frozen with the plan, or the plan's `budget_pct` overrides it); noise is INCONCLUSIVE, never FAIL or PASS; no benchmark command is UNSUPPORTED; `validate-performance.mjs` recomputes every status (and, with `--config`/`--plan`, the thresholds) and refuses performance claims without a measurement or against its direction; fixture with known answers.
- Deterministic result submission (`agent.sh submit`), class verified against the diff, expand/contract rule for destructive plans, English run artifacts, and the fixes of five end-to-end rounds (decisions A30–A39).
- Database guard: no agent touches a database file, runs a SQL client or a migration/seed command; the control plane detects changed database files (A40).
- The lead never approves: the runtime records the user's reply as the approval (A41).
- The QA plan is derived from the final plan and verified against it before freeze (A42); results cite immutable artifact snapshots (A43); a Stop hook keeps gate names, classes and states untranslated in the final report (A44).
- tdd-proof validates one cycle per criterion (A45); Claude specialists under an isolated-HOME Codex lead get the operator's HOME (A46).
- Faster CI (A76): self-test suites run as parallel scenario units in four shards, pull requests run Linux only (macOS on `main` and nightly), documentation-only pull requests skip the test jobs, and the `checks` job always reports.
- A `fix_scope` entry `path:symbol` (or `path:line`) scopes to its path, so a fix round no longer stalls at IMPLEMENTING on a symbol-qualified scope (A77).
- Every role asks all its questions in one NEEDS_INPUT round, enforced by `submit` and `record`; intent-grill's multi-round interview (the task author's `design/INTENT.md` rounds) is exempt (A70, A75).
- Deliberately not done (A91, `docs/decisions.md`): no new role, no end-of-task quiz, no separate decision memory, no numeric confidence score, no style catalogue, no deploy or release by the agent. New concept page `docs/concepts/evidence.md` (evidence classes, UNSUPPORTED, assumptions, metrics, benchmark); README capability table lists what each test actually exercises.
- Benchmark report (A90): `node tests/benchmark/benchmark.mjs` scores recorded results of the existing fixtures and e2e runs per skill (correct, missed, false positives, scope adherence, duration, tokens); no new scenarios, no model calls.
- `proofline insights [--run ID] [--json]` (A89): a read-only report of cost per run, role and model (tokens only where recorded, `n/a` otherwise) and recurring failures (repeated findings, gate FAILs, scope violations, UNSUPPORTED checks, repeated approvals) with suggestions; it never changes a rule, skill, config, ledger or metrics file.
- Metrics and cost (A80): versioned JSON records in `.agents/local/metrics/records.jsonl` with duration per dispatch, runtime-reported tokens (null when not reported, never estimated), turns, retries, delegations and the result per gate; `metrics: off` still disables everything.
- Assumption register (A79): a mandatory `## Assumptions` section in PLAN.md and EVIDENCE.md, checked by both validators; `agent.sh freeze`/`refreeze` refuse an unverified high-risk assumption until the user answers it (recorded as `accepted-by-user`), `agent.sh verify-assumptions` shows the register, and the completion report lists every unverified or accepted-by-user assumption.
- evidence-map `impact` mode (A85): the Explorer produces a versioned JSON impact report for changed symbols, files or a base ref (references marked exact, textual or heuristic, homonyms excluded, affected modules, contracts, tests) with the limits of static analysis and the unknown cross-repo consumers stated, plus a validator that re-checks every cited line; plan scope, test-trust diff mode, verify-proof and contract-proof read it through the documented interface.
- contract-proof skill (A83): the REVIEW `contract` focus proves the compatibility of changed OpenAPI, AsyncAPI, JSON Schema, GraphQL and protobuf contracts with an existing compatibility tool or a dependency-free built-in structural differ (unparseable files are UNSUPPORTED, never a pass), classifies every change by a direction-aware rule id, lists in-repo consumers from the impact report (outside consumers unknown), and fails a breaking change that PLAN.md `## Contracts` does not cover with versioning, migration or deprecation; `.agents/config.yaml` `contract.paths` / `contract.ignore` globs (frozen with the risk mapping) tune which changed files count; api-design designs, contract-proof verifies.
- Risk-adaptive pipeline (A78): deterministic risk signals (contract, migration, UI, dependency and config paths, optional content hints, PLAN.md flags) add focuses inside the existing gates; `agent.sh pipeline` shows each signal, its source and its check; an undeclared signal is a blocking finding; an unavailable check is UNSUPPORTED, never a PASS; the mapping is frozen with the plan. Every focus has its skill (A82-A87); a check that cannot run is UNSUPPORTED and only the user can waive it; a migration path makes the tier full.
- data-design migration validation (A84): the REVIEW_DATA `migration` focus applies migrations only on the test suite's own throwaway database, compares schema snapshots and seed rows, and reports lock, long-run, DDL-pattern and mixed-version risks; no such database is UNSUPPORTED, never PASS (`migration-check.mjs`, `validate-migration.mjs`, `fixtures/migration-validation`).
- concurrency-proof skill (A86) for the REVIEW `concurrency` focus: candidate sites from a dependency-free scanner, each finding a traced interleaving (two or more actors, `file:line` per step, checked against the repository and the diff) or a concurrent reproduction in the project's own test runner; reproduction is stated as ran or UNSUPPORTED, unproven risks are listed apart, PASS means no proven problem, and the validator rejects safety claims in the verdict; known-answer fixture `concurrency-proof`.
- ui-design (A81): on-demand references for a grounded creative direction (conform to `DESIGN.md`; redesign only on the task's request with the user's approval; no style catalogue), UX pattern comparison and spec self-critique; optional `ui.json` keys `creative_direction`, `ux_patterns`, `self_critique`, `criteria` (mandatory for COMPLEX/CRITICAL via `--task`/`--class`); per-criterion `visual_proof: required|not_required` with the PLAN `## UI` line `visual_proof: <AC ids|none>` and `--list-visual-proof`; the designer never approves its own design (validator rejects the claim); known-answer cases with traps.
- visual-proof skill (A82): the QA gate's `visual` focus measures changed screens in a browser the project or machine already has (overflow, horizontal scroll, hidden or covered controls, contrast, touch targets, focus order and visibility, every spec state rendered, form and modal behaviour, the project's accessibility scanner) with screenshots hashed into the report; hierarchy, density, consistency and typography are judged separately and fail only a written criterion; STANDARD = 2 viewports measured, COMPLEX/CRITICAL = every state x 3 viewports plus judged; no browser = UNSUPPORTED; verify-proof treats a `visual_proof` criterion without a proven visual result as MISSING. Fixture `fixtures/visual-proof` (planted overflow, contrast, missing state, small target; carousel and skip-link traps); its browser measurement runs on main/nightly CI only.
- Security extension (A88): the SECURITY `dependencies` focus now has its method in exploit-proof (`diff-manifests.mjs` manifest diff of added, removed and changed dependencies, transitive lockfile entries, install hooks, git or URL sources and unpinned ranges, checked against PLAN `## Dependencies`; license policy `security.licenses.allow|deny`; the project's own audit tool used only when it exists, `tool_unavailable` recorded when it cannot run, vulnerabilities only from its output) and the REVIEW `config` focus has its method in proof-review (`check-config.mjs`: variables used but not documented, plain-text secrets masked, feature-flag defaults and removed flags still referenced); fixtures `dependency-audit` and `config-consistency`.
- `SECURITY.md` and `CONTRIBUTING.md`; the Acknowledgments section is removed and D33 states that no third-party project is named.

## 0.0.1 — 2026-10-09

First release. Full scope, not yet proven on real projects.

- Lead plus eleven role sources (`roles/`), rendered by `adapters/generate.sh` into Claude Code agents, Codex agents and prompt prefixes.
- Seventeen method skills plus the `/proofline` command entry skill (`skills/`), including `proofline-lead`, and the test-trust and proof-review skills now maintained here.
- Deterministic control plane (`control-plane/`, installed as `.agents/`): lifecycle, classification, freeze, tiers, gates, fix loop, waivers, approvals, execution policy, failover and resume, enforced by `agent.sh` and git hooks (pre-commit, pre-push).
- `proofline` CLI: `init`, `upgrade`, `doctor`, `version`, `status`, `resume`, `queue`, `deliver`, `clean`, `task`, `design`, `run`, `review`, `audit`, `debug`.
- Claude Code plugin and marketplace manifest; Codex and terminal installer (`adapters/codex/install.sh`).
- Task adapters: markdown and GitHub (tested), Jira and Linear (contract only, not tested); per-target task templates.
- Documentation: concepts, guides (English and Turkish), generated roles and skills references.
- Tests: script self-tests, enforcement tests, skill fixtures.
