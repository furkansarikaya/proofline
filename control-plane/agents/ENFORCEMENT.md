# Enforcement matrix

"Script-enforced" means `.agents/scripts/agent.sh` (or a git hook in `.agents/githooks/`, or
`dispatch.sh`/`exec-policy.sh`) fails closed. "Policy-only" means only instructions stand behind it. Runtime
hooks (Claude Code, Codex) are an extra layer, never the foundation (D6). Never describe policy-only
behaviour as technically prevented.

| Rule | Classification | Mechanism |
|---|---|---|
| Active task selection | Script-enforced | `.agents/local/ACTIVE_RUN` absent or empty = no task for `status`; a malformed or dangling selector FAILS `status`. The git hooks never use it: they use `agent.sh open-runs` (every run directory not terminated and not cleaned up). |
| Role command boundary | Script-enforced for CLI commands | Default role `lead`. Gate roles may run only read-only commands plus `submit`/`record`/`gate`; the implementer adds `worker-evidence` and `handoff IMPLEMENTING` (never the reopen after a finding); other roles read-only plus `submit`/`record`. State commands (`classify freeze refreeze handoff approve waive answer terminate amend cleanup decide secret-scan ledger-note metrics-dispatch ask`) are lead-only. `AGENT_ROLE` is a declared claim. |
| Lead never writes a verdict | Script-enforced | `record` requires `ROLE` = `AGENT_ROLE` and rejects PASS/FAIL for `lead`; `gate` rejects the lead; gate records whose role is not the gate's owner count as `stale`. |
| Result protocol | Script-enforced | `submit` builds the header, fingerprint and hashes itself; `record` (called by `submit`) rejects a malformed header, wrong role or task, stale fingerprint, unregistered or mismatched artifact, an artifact outside the role's and focus's paths, malformed findings (PROTOCOL.md). |
| Evidence is re-derived, not read (A107) | Script-enforced in `submit` and `record` | `submit` runs the skill validator of the role and focus and uses its result (a declared `--validator-result` that differs is refused); cited evidence files must exist in the run with the cited sha256 (`EVIDENCE:` lines, checked again by `record`); a PASS re-runs up to three recorded reproduced commands that are configured `commands.build|test|lint` or PLAN `## Verification commands` entries, and a differing exit status or output line is FAIL. Residual: focuses without a mapped validator keep the findings-derived result; a measured, traced or judged evidence file is checked for existence and hash, not re-derived. |
| Provenance of gate records, waivers, approvals | Script-enforced detection | only files bound `<dir>/<file>@<sha256>` in the ledger chain by their writing command count; `validate` names the others. A same-user actor who appends correctly chained ledger entries is not stopped (the chain is unkeyed). |
| Low-confidence PASS does not count | Script-enforced | recorded `pass_low`; never satisfies a gate. |
| Lead never writes product code (orchestrated) | Script-enforced detection at every transition and gate; write-time blocking is a runtime hook (phase 3) | `window-open`/`window-close` attest the implementer's tree; any other change FAILS. |
| No swarm, one implementer, explorer bound | Policy-only | Role instructions and mode policy; the repository has no agent-spawn interceptor. |
| Classification selects artifacts and QA | Script-enforced (the choice of class is a lead judgment) | `classify` lead-only; `freeze` requires exactly the class artifacts; TRIVIAL scope bound and no executable code in a TRIVIAL scope (A115); the class is frozen and sealed. |
| Destructive plan is CRITICAL | Script-enforced | `freeze` forces CRITICAL when `## Data` starts `destructive: yes`; `classify` below CRITICAL FAILS; an invalid first line FAILS. |
| Tier from the diff, never decreasing | Script-enforced | `tier` computes from the diff; `pipeline.tier` is recorded by the lead, sealed by the ledger, and the effective tier is the maximum. |
| Required gates per class and tier | Script-enforced | `required_gates`; a gate outside the set is refused; CODE_DONE needs all `pass`/`waived`. |
| Gates bound to exact content and artifact | Script-enforced | fingerprint, patch manifest, frozen hashes, artifact sha256, raw result sha256. |
| Secret scan always, never waivable | Script-enforced | `secret-scan` records SECRETS; `request-approval`, `waive` and gate evaluation refuse waivers of SECRETS and SECURITY. Knowledge-scope files (written after CODE_DONE) are scanned at DONE and `delivery-check`. The scanner's coverage is the scanner's (secret-scan.sh). |
| Fix loop bound | Script-enforced | rounds ≤ `review.max_fix_rounds`; fix inside `fix_scope` or a plan-scope path sharing an acceptance criterion with a failing finding (A123); FAILED only after exhaustion; a refreeze after exhaustion needs a `budget` approval. |
| Waivers need the user | Script-enforced structure; identity as below | `waive` needs a `waive:<ID>` approval naming the finding, bound to the failing gate record's sha256 and granted after it. |
| Approvals from the user | Script-enforced structure; the user's identity is declared | TTY input or a prompt capture newer than the request, with matching sha256, an approval phrase and a kind word, single-use per capture (A106: session+time+sha, never per text). Captures, approval requests and approval files count only as regular files (no symlink) with one hard link on a directory chain without symlinks below the project root, so a capture or approval cannot be a link to a file an agent controls. Residual: no writer marker exists, so a same-user process that writes a well-formed regular file into `.agents/local/prompts/` forges a capture; the capture hook and the runtime hook's denial of agent writes to `.agents/local/` (except the lead's `.agents/local/assignments/`) close it further. Phrase matching is substring-based and does not detect negation ("do not approve"). |
| Supervised plan approval, scope approval | Script-enforced | `freeze`/`refreeze` require and consume them, bound to the PLAN.md sha256. |
| Destructive approval (and single_step) | Script-enforced | `handoff IMPLEMENTING` from PLANNED requires and consumes them, bound to the frozen PLAN.md sha256; a refreeze that changes the PLAN.md of a destructive plan returns an IMPLEMENTING or IMPLEMENTED run to PLANNED, so the same gate asks again for the new hash (K-6). |
| Questions relayed verbatim | Script-enforced storage and `answered_by`; relaying verbatim is policy-only | `questions/NNN.md` verbatim (a specialist's NEEDS_INPUT through `submit`, the lead's own question and `dispatch.sh`'s `failover: ask` question through the lead-only `ask`); `answered_by: user` only when contained in the latest user prompt capture; CODE_DONE FAILS and `next` stops while questions are pending. |
| Commit/push need gates and approval | Script-enforced in git hooks (`githooks/`, P1-B) | pre-commit: identity guard, the task branch of an open run (`open-runs`; emptying ACTIVE_RUN opens nothing), `delivery-check`, `approval-consume commit <fingerprint>`; pre-push: only an open run's task branch, `approval-consume push`. Residuals: `git commit --no-verify` / `git push --no-verify` skip the hooks entirely and are blocked only by the Claude Code / Codex PreToolUse hook (a runtime layer, not git); the "human at a TTY" exemption is detected from a terminal on stderr, so a process that allocates a pseudo-terminal (`script(1)`, `expect`, `unbuffer`) without `AGENT_ROLE` passes as a human (it still needs the gates, never the approval); a user who disables `core.hooksPath` bypasses them (`doctor` checks it). `dispatch.sh` BLOCKS a dispatched step that changes `.git/config` (e.g. `core.hooksPath`) or HEAD. |
| Freeze of task, evidence, plan, QA plan, policy | Script-enforced | sha256 in RUN.yaml; `verify-freeze`. |
| Scope `new: true` | Script-enforced at freeze | a `new: true` path that exists FAILS; a path without it that is missing FAILS. |
| Planning freshness, task-source contract | Script-enforced for local Markdown and `none` sources | `freshness`; projection hash; `task-source-status`, `task-source-relocate`; adapter confinement. |
| Run artifact registry | Script-enforced | unknown files in the run directory FAIL `verify-scope`, gates and `validate` (WORKFLOW.md table). |
| Stray file in a run directory is recoverable | Script-enforced (A119) | lead-only `discard-stray <ID> <file-name>`: one top-level regular file, never a symlink, never a protected name (compared case-insensitively), ledgered with its sha256. Strays in subdirectories are not handled. |
| `sed -i` leaves no backup-suffix stray | Hook-enforced (heuristic, A119) | the hook denies `sed -i` followed by an option-looking word or with letters glued to `-i` (`-iE`): BSD sed takes them as the backup suffix. |
| Branch isolation | Script-enforced for a RUN.yaml with `repository.task_branch` | `branch` creates `<git.branch_prefix><ID>-<slug>` from the canonical tip; transitions require that branch; a conflicting branch is never reused. |
| Baseline of user changes | Script-enforced | fingerprints; a later change to a user file is task scope. |
| Worker evidence and TDD | Script-enforced for a run with `worker_evidence:` | RED/GREEN per non-exempt path, bound to frozen hashes and the topology's owner. Order (A97): `worker-evidence` refuses GREEN and REFACTOR for a path with no earlier RED record, GREEN while no implementation path (a scope path that is not a test file) differs from the scope snapshot stored in that RED record, and REFACTOR before a GREEN or FIX record. Residual: the snapshot compares file hashes, so any edit of an implementation path satisfies it; a TDD-exempt path is not held to RED. |
| Ledger and manual rewind | Script-enforced detection | hash chain sealing the RUN.yaml lifecycle fields (state, knowledge, awaiting_input, autonomy, handoff, class, review, tier, completion report, task source). A same-user actor who rewrites RUN.yaml and re-seals the whole ledger is not stopped. |
| Knowledge transaction scope | Script-enforced | `knowledge_scope_root`; DONE, delivery-check and validate check both scopes; DONE and delivery-check secret-scan the knowledge files. |
| Completion report | Script-enforced structure and numbers | required sections per run; published and verified through the adapter. `publish-completion-report` (A143, C-22) appends the Facts block generated by `agent.sh report-facts` (gates with status and finding ids, fix rounds, refreezes, files changed, worker-evidence test runs) and refuses a number beside the words tests, gates, fix rounds or refreezes that is not a recorded value. Digits and the English number words one to twenty are read when they stand directly beside the word; a verb ("step 3 tests the lookup"), "test files/cases/suites" and "0 tests failed" are not counts. Other phrasings ("cases", "assertions"), table cells and prose claims are model text and are not read. No record carries the number of individual tests; the Facts block shows worker-evidence run records (total, ended pass, ended fail). |
| Read roles change nothing in the project tree (A143; C-3) | Runtime hook (heuristic) | While a run is open the PreToolUse hook denies QA, reviewer, security reviewer and verifier any write to the project working tree: Edit/Write/NotebookEdit on a project path, redirections, `tee`, `cp`/`mv`/`rm`/`truncate`/`dd of=`/`install`, in-place editors (`sed -i` in every spelling, `perl -i`, `ruby -i`, `awk -i inplace`, `ed`, `ex`, `vi`/`vim`, `patch`) and `git checkout`, `apply`, `stash`, `reset`, `restore`, `clean`, `switch`, `rebase`, `merge`, `pull`, `rm`, `mv` unless the effective directory is a registered evidence worktree. Allowed: that worktree (created under `$TMPDIR` in its own call, used with a literal path), the role's own run files and `.agents/runs/<ID>/scratch/`. `find -delete`, `find -exec <writer>` and `xargs <writer>` count too. A path the text cannot resolve (variable, substitution, `..` component, missing directory) is read as the project, so `W=$TMPDIR/x; git -C $W apply` is denied for a read role: create the worktree in its own call and use its literal path. Active only while a run is open. Not seen: `python`/`node` or any interpreter script that writes by itself. |
| Execution policy, escalation | Script-enforced resolution and recording | `decide` → `exec-policy.sh resolve`; decisions ledgered; the model a runtime really used is the runtime's. |
| Terminal outcomes, cleanup, reopen | Script-enforced | `terminate`, `cleanup`, `amend` as in WORKFLOW.md. After the delivery commit `cleanup` needs `base_sha` an ancestor of HEAD, the task-owned patch measured from `base_sha` equal to the CODE_DONE patch and committed exactly, and every required gate passing; then the run directory and the run's `.agents/local/assignments/<ID>/` (refused if it, `.agents/local` or `.agents/local/assignments` is a symlink or the run's path is not a plain directory) are deleted and the hooks see no open run. |
| Runtime hooks in headless Codex workers | Runtime layer | `dispatch.sh` runs `codex exec --dangerously-bypass-hook-trust`: a headless run cannot answer Codex's hook-trust prompt, and without the flag the project's proofline hooks would not load for the worker. The flag trusts only the hooks this project installed; the enforcement stays in `dispatch.sh` (product-tree fingerprint for non-writing roles, attested window for the implementer, `.git/config` and HEAD unchanged) and `agent.sh`. |
| Nothing is written outside the copy (A56, A97; C-18) | Runtime hook (heuristic) | The PreToolUse hook denies, with or without a run, every shell write whose resolved target is an absolute path outside the project root, the registered git worktrees and `/dev/*`: redirections (`>`, `>>`, `2>`), `tee`, `cp`/`mv`/`install`/`rsync`/`ln` targets, `touch`/`rm`/`truncate`, and `mktemp` without a template inside the scratch folder; `/tmp`, `$TMPDIR`, `/var/folders`, `~` and `$HOME` spellings are expanded first. The message names `.agents/runs/<ID>/scratch/`. Residuals: policy-only. Writes the tokenizer cannot see (a script or interpreter opening a file by itself, `eval`, a computed path, `cd` followed by a relative path) are not matched; quoted strings and heredoc bodies are skipped on a best-effort basis, and the older raw-text check for `/tmp` paths in any argument can still refuse a quoted `/tmp` string. |
| Databases are never touched; destructive steps never run before approval (A40) | Runtime hook (strict heuristic) + script-enforced detection | While a run is open the PreToolUse hook denies, for every role including the lead: any command word, argument or redirection target that names a database file (`database.paths`), a SQL/database client (`database.clients`; sqlite-family clients only against `:memory:` or a scratch file under `$TMPDIR` outside the project), a migration, seed or schema command (`database.migrate_commands`), and the Read, Grep, Glob, Edit, Write, NotebookEdit and apply_patch tools on a database file. The only database an agent may meet is a test suite's own throwaway one. `agent.sh start` records size and mtime of every database file; `freeze`, IMPLEMENTED, CODE_DONE and DONE fail when one changed, appeared or vanished (`agent.sh db-check`). Residuals: a script that opens a database by itself is seen only after the fact; an unconfigured client or migrate command is not matched. |
| The lead never approves (A41; D3, D13) | Runtime hook + script-enforced verification | The PreToolUse hook denies `agent.sh approve` and `approve-pending` for every model (lead and subagents), with or without an active run. The runtime's prompt hook records the user's reply as a capture and then runs `agent.sh approve-pending`, which attempts `approve` for every open request; `approve` itself still verifies the capture (newer than the request, matching sha256, approval phrase and kind word, single-use) or a TTY line. A terminal user may run `approve` by hand. Residual: a runtime without a prompt hook records no approval until the user runs `approve` in a terminal. |
| Final report keeps identifiers untranslated (A44; TR-2) | Runtime hook (Stop) | Once per reporting state (CODE_DONE, DONE, FAILED, BLOCKED) the Stop hook compares the lead's final message with `agent.sh report-tokens <ID>` (the state, the class and every required gate name) and sends the lead back once when one is missing; a second stop is accepted. A message that carries them satisfies the check for that state. Residual: presence is checked, not that no translation sits next to the identifier; a runtime without a Stop hook, or a Stop input without the last message (no transcript either), is unchecked. |
| One NEEDS_INPUT round per role (A70, C-14); intent-grill's interview exempt (A75) | Script-enforced in `submit` and `record` | A second NEEDS_INPUT from the same role (and reviewer focus) in a run is rejected. The exemption is keyed on role task_author, artifact `design/INTENT.md` (or the snapshot `submit` made of it) and its `## Status` being `in-progress`; rounds are bounded only by the user's replies. Residual: the task author writes that file and status itself, so the exemption is a trust convention checked by shape; the pre-run intake is outside the script rule. |
| Metrics | Best effort | `.agents/local/metrics/history.tsv` and `records.jsonl` (A80), written by the control plane (dispatch records through the lead-only `metrics-dispatch`), no model-written text copied in; never blocks a command. |

## Evidence strength

Hashes, fingerprints, ledger chains and gate bindings are machine-verifiable. Roles, the independence of
reviewers, and the identity of the user behind an approval are declared claims unless the runtime supplies
auditable identities. Which layers apply to a run is decided by the policy keys in its RUN.yaml
(`worker_evidence`, `tdd`, `completion_report`, `lifecycle_gates`, `repository.task_branch`); the template
carries them all.
